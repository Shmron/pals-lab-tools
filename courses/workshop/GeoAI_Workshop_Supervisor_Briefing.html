What this is

A progressive, hands-on course that takes surveyors with basic Python from raw spatial health data to a working natural-language query interface over a real exposure database — built around a realistic pregnancy-cohort case study (heat & air pollution exposure → birth outcomes). It follows the WorldQuant University format: Concept → Worked example → Do-it-yourself → Auto-check.

How it's covered — pedagogy & pacing

Teaching method (per notebook)

  • Concept note — short, plain-language framing of the problem
  • Worked example — instructor-run, fully solved
  • Do-it-yourself — student fills in stubs (nbgrader-stripped)
  • Auto-check — instant ✅/❌ feedback, no waiting on a marker

Difficulty curve

  • 01–03 (65 min): foundational — pandas, plotting, joins. Gentle ramp.
  • 04 (25 min): conceptual peak — temporal-spatial assignment logic is the hardest idea in the course
  • 05 (20 min): relief module — lower point value, mostly observational, non-blocking if EE/internet fails
  • 06 (30 min): capstone — synthesises everything into one query interface; highest reward-to-effort module

Content balance

  • All data synthetic and locally generated — zero dependency on venue internet for the core path
  • Earth Engine is the only live-internet component, and it's explicitly non-blocking
  • Basemaps tuned (CartoDB tiles, fixed zoom) — full notebook runs in ~12–15s, not minutes

Where time is "spent"

  • ~36% of contact time (65/180 min) builds foundational skills surveyors mostly already half-know
  • ~14% (25 min) on the one genuinely novel idea (timeline assignment)
  • ~28% (50 min) on applied extraction + capstone GeoAI — the most memorable, most "wow" content

The capstone: GeoAI in plain English

Notebook 06 ends with a free-text question box. A participant types a question like "how many participants have PM2.5 above the WHO guideline?" — the question is sent to a Claude-backed endpoint, translated to safe SQL, executed against their own DuckDB exposure database, and returned as a table with an auto-generated chart, the same chart-selection logic used in the production PRECISE Catalogue assistant ("Shmron AI").

Guardrails already in place

  • Generated SQL is validated as read-only/safe before execution (no writes, no destructive statements)
  • Offline fallback: pre-written demo Q→SQL pairs if the endpoint is unreachable
  • Per-student token budget (200k each) — students explore freely without risk of burning the shared API budget
  • Admin portal now surfaces every student's usage live, with one-click budget edits

Why this matters for the audience

  • Surveyors leave having used an AI-over-database tool, not just heard about one
  • Demonstrates the same architecture used in a live production system (PRECISE), not a toy demo
  • Directly addresses the "GIS → climate-health" skills gap the YSN audience is targeting

Recommendations going into 25 June

Keep as-is

  • The single-narrative data flow (01→06) — don't fragment into standalone demos
  • Auto-check cells — instant feedback is what makes self-paced sections survivable in 3 hours
  • Non-blocking Earth Engine design — protects the schedule against venue Wi-Fi failure

Tighten before the event

  • Module 04 is the cognitive bottleneck — consider a 2-minute whiteboard sketch of the "timeline anchoring" idea before participants touch code
  • Confirm facilitator has a backup plan if >20% of participants are slower-paced (guide already allows skipping worked examples in 01–03)
  • Do a dry run of the GeoAI capstone on workshop-day Wi-Fi specifically — it's the highest-impact, least internet-tolerant component
Overall recommendation: the course is ready to run. Risk is concentrated in two places — Module 04's conceptual difficulty and the GeoAI endpoint's live-network dependency — both already have mitigations built in (skip-ahead guidance; offline demo fallback). No structural changes needed before 25 June.
Watch item: 30 min is tight for Module 06 given it carries the highest point value (11) and the capstone demo. If running behind schedule, protect GeoAI time by trimming the EDA/mapping sub-section first — it's reinforcement, not new conceptual ground.
