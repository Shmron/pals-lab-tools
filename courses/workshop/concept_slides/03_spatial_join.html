Concept: the four-step join pattern

Notebook 02 used find_nearest_grid_cells() as a black box. Here we open it up — this exact four-step pattern is the workhorse of the entire course; everything from here on is a variation of it.

1. tree = cKDTree(grid[['lat','lon']]) # index the grid once 2. dist, idx = tree.query(points[['lat','lon']]) # nearest cell per point 3. points['grid_id'] = grid.iloc[idx]['grid_id'].values 4. result = points.merge(grid, on='grid_id') # attach temp/PM2.5/NDVI/...
Always verify the join: check result['temp_mean_c'].notna().all() — a missing value after a join means something went wrong (a coordinate outside the grid extent, a bad merge key).

Concept: when is "flat-plane" distance OK?

The join uses Euclidean (straight-line) distance on raw lat/lon — not true geodetic (sphere-surface) distance. That's a simplification, and knowing when it's safe is the actual lesson here.

Why it's acceptable here

  • Zimbabwe spans ~7° lat × 7° lon (~700 km) — flat-plane distortion here is <0.5%
  • Far smaller than the 27 km grid cell size we're matching against
  • Same grid spacing on both axes keeps the approximation symmetric

What changes once points move (Notebook 04)

  • So far: static points joined to a single-date grid
  • Next: each participant's location changes between visits
  • And the grid itself has one row per cell per day for ~700 days
Watch for: this approximation breaks down at continental scale or near the poles — always check your study area's extent before reusing this shortcut elsewhere.
